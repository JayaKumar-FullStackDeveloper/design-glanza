TODO-5
Classification: DESIGN (documented inside TODO-2's file + TODO-1's
                schema)
File/module: design-reference-engine/figma-reference.md,
             design-reference-engine/figma-context.schema.json
Dependencies: TODO-1, TODO-2, TODO-4
Purpose: Define the STRENGTHENED Figma Design Context shape per
         correction #4 - enough information to create new screens that
         genuinely belong to the existing Figma product, not just enough
         to pass a schema check.
Implementation details - the full normalized shape:

  figma-context.json
  |-- source            { fileKey, nodeIds[], fetchedAt,
                           inspectionMode: "structured" | "image-fallback" }
  |-- pages             [{ pageName, pageId, frameIds[] }]
  |-- screens           [{ frameName, frameId, exportedImagePath, role,
                            confidence }]
  |-- tokens
  |     |-- colors      { semantic + raw swatches, by collection + mode
                           (light/dark), confidence per value }
  |     |-- typography  { family, scale steps, weights, line-height,
                           pairing, confidence per value }
  |     |-- spacing     { base unit, step scale, confidence per value }
  |     |-- radius      { scale, per-component-type mapping if present }
  |     |-- elevation   { shadow steps, usage mapping }
  |     `-- sizing      { control sizes, icon sizes, breakpoint widths }
  |-- components
  |     |-- components  [{ name, purpose/role, nodeId }]
  |     |-- variants    [{ componentName, variantAxis, values[] }]
  |     |-- properties  [{ componentName, propName, propType, default }]
  |     `-- states      [{ componentName, variantName -> mapped
                            Design-Glanza state (initial/loading/success/
                            empty/error/disabled/etc.) }]
  |-- patterns          [{ name, composedOf[] - e.g. a recurring
                            "filter bar + table" combination }]
  |-- layouts           [{ frameName, autoLayout{ direction, gap,
                            padding, alignment }, gridHint }]
  |-- responsive        [{ frameName, breakpointVariant, adaptation
                            decision if inferable }]
  |-- interactions       [{ trigger, componentOrFrame, behavior if
                            stated/inferable (hover/press/transition) }]
  |-- iconography        { stroke vs fill convention, size consistency }
  |-- imagery            { photography vs illustration use, treatment }
  `-- visual-rules       { hierarchy signals, naming conventions
                            observed in layer/component names, any
                            do/don't pattern implied by consistent
                            vs. inconsistent usage }

  - EVERY leaf value carries a confidence tag: "explicit" (directly
    read from Figma's own structured data - a bound variable, a named
    variant, an auto-layout property), "inferred" (a reasonable reading
    from visual inspection, e.g. "looks like an 8px base unit"), or
    "assumed" (no signal at all, Design-Glanza default used) - the same
    Explicit/Inferred/Assumed vocabulary used everywhere else in this
    engine (Rule 10), never a new tagging scheme.
  - Interactions/states/patterns sections are allowed to be partially
    populated - Figma does not always encode behavior; what can't be
    read structurally is marked inferred/assumed or left as a stated gap,
    never fabricated.
Validation requirements:
  - Confirm every field in this tree has a corresponding schema entry in
    TODO-1.
  - Confirm every field maps to at least one concrete consumer named in
    TODO-7 (the contract) - a field with no downstream consumer is
    scope creep and should be trimmed before implementation.
